## What happened and why

The update type is patch, so the automerge rule matches. The PR body shows `🚦 Automerge: Enabled.`

A required check failed, so GitHub did not merge. Renovate does not hide a failed PR and does not retry it. The PR stays open, and a person must act. Automerge removes the work for green updates. Red updates still come to a person.

The developer pushed a commit to the Renovate branch. After that commit, Renovate no longer rebases the branch or pushes to it. The Dependency Dashboard lists the PR under "PR Edited (Blocked)" until the merge. GitHub auto-merge is still on. After the checks pass, GitHub merges the PR.

With `platformAutomerge: false`, the last step is different. Renovate merges by itself in a later run. Before the merge, Renovate makes sure that the branch has no commits from other authors. If it finds one, it does not merge, and a person must merge the PR.
