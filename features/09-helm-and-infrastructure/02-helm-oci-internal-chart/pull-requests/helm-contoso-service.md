## What happened and why

The `helmv3` manager read the dependency `contoso-service` in `charts/orders/Chart.yaml`. The `repository` starts with `oci://`. An OCI registry stores Helm charts the same way as container images. So Renovate used the `docker` datasource with the package name `contoso.azurecr.io/helm/contoso-service`. The datasource read the tags of that repository in the registry and found 1.5.0.

The title says "Docker tag", because the `docker` datasource sets the commit message topic `{{{depName}}} Docker tag`. The update is still a chart update. The name in the title is `contoso-service`, because `depName` is the `name` from `Chart.yaml`.

The registry is private. Renovate used the host rule with `hostType: 'docker'` for two steps:

1. The `docker` datasource used the user name and the password to read the tags.
2. Before the lock file update, Renovate logged in to the registry with Helm.

The second step ran these commands:

```sh
helm registry login --username renovate-pull --password *** contoso.azurecr.io
helm dependency update charts/orders
```

If the host rule has `hostType: 'helm'`, the `docker` datasource does not use it. Then Renovate cannot read the tags. The Dependency Dashboard then shows the warning "Renovate failed to look up the following dependencies" with `contoso-service`.

The package name has no link and the PR has no release notes. The chart `contoso-service` has no `home` and no `sources` in its `Chart.yaml`, so Renovate has no source repository. If you add `sources` with the URL of the GitHub repository of the chart, Renovate links the name and looks for release notes there.
