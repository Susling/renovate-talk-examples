## What happened and why

The `helm-values` manager read `charts/orders/values.yaml`. It looked for objects under a key that ends in `image`. The object under `contoso-service.image` has `registry`, `repository` and `tag`. So the manager made one dependency:

| Field in Renovate | Value | Comes from |
|---|---|---|
| `depName` | `contoso.azurecr.io/orders-api` | `registry` and `repository` |
| `currentValue` | `1.7.2` | `tag` |
| `datasource` | `docker` | Always `docker` for `helm-values` |

The `docker` datasource used the host rule for `contoso.azurecr.io` and read the tags of `orders-api`. The newest tag was `1.8.0`.

Renovate changed only the `tag` line. `helm-values` has no lock file and runs no Helm command.

The title and the branch name contain the full image name with the registry. In the branch name, Renovate replaces `/` with `-`.

The image has no label `org.opencontainers.image.source`. So Renovate does not know the source repository of `orders-api`. The package name has no link and the PR has no release notes. If the build of `orders-api` adds that label with the URL of the GitHub repository, Renovate adds the link and looks for release notes there.
