## What happened and why

The file name `k8s/redis.yaml` matched the pattern in `managerFilePatterns` of the `kubernetes` manager. The file contains `apiVersion:` and `kind:`, so the manager read it. It found two kinds of dependencies:

| Line | Dependency | Datasource | Result |
|---|---|---|---|
| `image: redis:7.4.1` | `redis` | `docker` | Update to 7.4.2, this PR |
| `apiVersion: apps/v1` with `kind: Deployment` | `Deployment` | `kubernetes-api` | `apps/v1` is the current API version, no PR |

The image `redis` has no registry in its name, so the `docker` datasource read the tags from Docker Hub. Redis 7.4.2 was published on 2025-01-06.

The title says "Docker tag", because the `docker` datasource sets the commit message topic `{{{depName}}} Docker tag`.

The official `redis` image has no label `org.opencontainers.image.source`. So the package name has no link and the PR has no release notes.

The `Service` in the same file gave no dependency. It has no image. The `kubernetes-api` datasource has a list of kinds with more than one API version, for example `Deployment`, `Ingress` and `CronJob`. `Service` is not in that list.
