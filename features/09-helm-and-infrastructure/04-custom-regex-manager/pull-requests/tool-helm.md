## What happened and why

No built-in manager reads `deploy-tools.yaml`. The custom regex manager in [`../renovate.json5`](../renovate.json5) matched the file name. Its regular expression found two matches, one for each comment line that starts with `# renovate:`. Each match gave one dependency:

| Field in Renovate | First match | Second match |
|---|---|---|
| `datasource` | `github-releases` | `github-releases` |
| `depName` | `helm/helm` | `kubernetes/kubernetes` |
| `currentValue` | `v3.16.4` | `v1.32.1` |

The `github-releases` datasource read the releases of the GitHub repository `helm/helm`. The newest release on 2025-01-17 was v3.17.0, from 2025-01-15. So Renovate opened this PR.

`kubectl` got no PR. The newest release of `kubernetes/kubernetes` on 2025-01-17 was v1.32.1, and the file already has that version.

The title says "dependency helm/helm", because the `github-releases` datasource sets no commit message topic. Renovate then uses the default topic `dependency {{depName}}`. In the branch name, Renovate replaces `/` with `-`.

The release notes heading shows `vv3.17.0`. This is real Renovate behavior: the heading template adds a `v` in front of the version, and a version from `github-releases` already starts with `v`.

The release name "Helm v3.17.0" follows the heading. Renovate removes the version from the start of a release name, but this name starts with "Helm". Renovate also changed the `##` headings of the release body to `####`, so they fit inside the PR body.
