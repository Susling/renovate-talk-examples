## What happened and why

The `helmv3` manager read the `dependencies` list in `charts/contoso-argocd/Chart.yaml`. The dependency has a `name`, a `version` and an HTTPS `repository`. So Renovate used the `helm` datasource. The datasource downloaded `https://argoproj.github.io/argo-helm/index.yaml` and read the versions under `entries.argo-cd`. On 2025-01-17 the newest version was 7.7.16, published on 2025-01-14.

Renovate changed the version in `Chart.yaml`. Then it updated `Chart.lock` with two Helm commands:

```sh
helm repo add argo-cd https://argoproj.github.io/argo-helm --force-update
helm dependency update charts/contoso-argocd
```

The second command writes a new `digest` and a new `generated` time into `Chart.lock`. It also downloads `argo-cd-7.7.16.tgz` into `charts/contoso-argocd/charts/`. Renovate commits only `Chart.lock`, because the option `helmUpdateSubChartArchives` in `postUpdateOptions` is off.

The title says "Helm release", because the `helm` datasource sets the commit message topic `Helm release {{depName}}`.

The release notes come from GitHub. Each version in `index.yaml` has a download URL on `github.com/argoproj/argo-helm/releases`. Renovate takes the source repository from that URL. The argo-helm repository has one GitHub release per chart version, with the tag `argo-cd-7.7.16`. Renovate matches the tag by the chart name. The repository holds many charts, so the "Full Changelog" link of the GitHub release starts at a release of another chart. The "Compare Source" link from Renovate compares two `argo-cd` tags.

The table has the columns Package, Update and Change. The `mergeConfidence:age-confidence-badges` preset adds Age and Confidence only for npm, NuGet and five other datasources, not for `helm`. The `helmv3` manager sets no dependency type, so Renovate hides the Type column.
