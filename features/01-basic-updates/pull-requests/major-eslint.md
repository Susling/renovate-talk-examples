## What happened and why

The first number of the version changed from 8 to 9, so the update type is major. With `config:recommended`, Renovate puts a major update in its own PR (`separateMajorMinor`). The title says `to v9` and not `to v9.18.0`, because the major version is the important fact.

The branch name is `renovate/major-eslint-monorepo` and not `renovate/eslint-9.x`. The preset `group:monorepos` in `config:recommended` puts every package from the GitHub repository `eslint/eslint` in the group "eslint monorepo". The branch name always comes from the group. This PR has only one package from the group, so the title uses the package name. Feature 02 explains the monorepo groups.

The `lint` check fails. ESLint 9 uses `eslint.config.js` by default, and this repository still has an `.eslintrc.json` file. Renovate changes only the version numbers. It does not migrate configuration files or source code. A developer must push the migration to the same branch.

> [!TIP]
> If you push a commit to a Renovate branch, Renovate no longer updates that branch. The Dependency Dashboard then lists the PR under "PR Edited (Blocked)". See [feature 04](../../04-dependency-dashboard/README.md).
