## What happened and why

The `npm` manager read `"@contoso/ui-components": "2.4.0"` from `package.json`. The `.npmrc` file sends the `@contoso` scope to GitHub Packages. The npm datasource got six versions from there. Version 2.4.0 was not one of them.

The package rule in the configuration sets `rollbackPrs: true` for `@contoso/**`. With that option, Renovate first looks for versions that match the current value `2.4.0`. It found none, so it made a rollback update:

1. Renovate kept the versions lower than 2.4.0: 2.2.0, 2.3.0, 2.3.1, 2.3.2 and 2.4.0-rc.1. It dropped 3.0.0-beta.1.
2. The current value 2.4.0 is a stable version. So Renovate kept only the stable versions and dropped 2.4.0-rc.1.
3. Renovate took the highest of the remaining versions: 2.3.2.
4. Renovate wrote 2.3.2 into `package.json` and ran `npm install` to update `package-lock.json`.

The PR has no release notes. Renovate shows the release notes of the versions above the current version, and a rollback has none.

The update type is `rollback`. The `mergeConfidence:age-confidence-badges` preset sets the Age and Confidence columns only for `patch`, `minor` and `major`. So this table has the default columns: Package, Type, Update and Change.

The design system team can publish 2.4.1 before anybody merges this PR. Then the next run makes two updates for the package: this rollback to 2.3.2 and a normal update to 2.4.1. Each update gets its own branch and PR. If you merge the update to 2.4.1, the current version exists in the registry again. Renovate then closes this rollback PR on its next run.
