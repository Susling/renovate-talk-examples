## Before the PR

On 2025-01-14, the maintainers published FluentAssertions 8.0.0 on NuGet. Version 7.x has the Apache-2.0 license. Version 8.0.0 has the Xceed license. Commercial use of 8.x needs a paid license.

A developer merged PR #430 "Update dependency FluentAssertions to v8" before the team saw the license change. The build did not fail, because the code of 8.0.0 works. The team decided to go back to 7.x and to stay there.

Version 8.0.0 is still in the registry. So a plain `rollbackPrs: true` does nothing, because Renovate finds the current version. The rule in the configuration hides 8.x from Renovate with `extractVersion`:

## What happened and why

The `nuget` manager read `Version="8.0.0"` from `WebApi.Tests.csproj`. The NuGet datasource got the versions of FluentAssertions from api.nuget.org. Then the package rule changed the list:

1. `extractVersion: '^(?<version>[0-7]\\..+)$'` dropped every version that does not start with a digit from 0 to 7. Version 8.0.0 was not in the list anymore.
2. `rollbackPrs: true` told Renovate to look for a lower version, because no version in the list matched 8.0.0.
3. The current value 8.0.0 is a stable version. So Renovate kept only the stable versions below 8.0.0.
4. Renovate took the highest of the remaining versions: 7.2.2.
5. `rangeStrategy: 'replace'` let Renovate use 8.0.0 as the current version. With the NuGet default `bump`, Renovate drops the rollback before it makes a branch.
6. Renovate wrote 7.2.2 into `WebApi.Tests.csproj`.

`allowedVersions: '(,8.0.0)'` did nothing in this PR. It is a second guard. If somebody changes `extractVersion` later, Renovate still proposes no update to 8.0.0 or higher.

The update type is `rollback`. Package rules for `patch` or `major` updates do not match it. So a rule with `automerge: true` for patch updates does not merge this PR.
