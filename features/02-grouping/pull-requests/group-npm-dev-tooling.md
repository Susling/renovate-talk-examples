## What happened and why

The three packages come from three different repositories, so no monorepo rule matches them. The `packageRules` entry with `groupName: 'npm dev tooling'` puts them in one PR. The branch name comes from the group name: `renovate/npm-dev-tooling`.

The packages go to different versions, so the title has no `to v...` at the end. The release notes show one block per source repository.

The configuration section shows the line `👻 Immortal` and not the line `🔕 Ignore`. If you close this PR without a merge, Renovate makes it again in the next run. The reason is `recreateWhen`. Its default value `auto` recreates a closed PR for a group with mixed versions. To stop one update, add a rule with `enabled: false` for that package, or use the Dependency Dashboard.

The rule has `matchUpdateTypes: ['minor', 'patch']`. When prettier 4.0.0 comes out, Renovate opens a separate PR "Update dependency prettier to v4" outside the group.
