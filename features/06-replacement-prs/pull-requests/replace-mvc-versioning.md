## What happened and why

`Microsoft.AspNetCore.Mvc.Versioning` 5.1.0 is the newest version, so a normal update does not exist. On nuget.org, the package is deprecated, and the deprecation names `Asp.Versioning.Mvc` as the alternate package. The preset `replacements:all` has no rule for this package. For this reason, the repository adds its own package rule:

```json5
{
  matchDatasources: ['nuget'],
  matchPackageNames: ['Microsoft.AspNetCore.Mvc.Versioning'],
  replacementName: 'Asp.Versioning.Mvc',
  replacementVersion: '8.1.0',
}
```

An own rule gives the same PR as a rule from `replacements:all`. The title, the branch and the note come from the option `replacement`, so the note also says "community suggested". The value 8.1.0 is the newest version of `Asp.Versioning.Mvc` on 2025-01-17. Version 8.x needs .NET 8, and the project uses `net8.0`.

The nuget datasource does not read the alternate package from nuget.org. Without the package rule, Renovate opens no PR for this package. But all 44 versions on nuget.org are deprecated, so the Dependency Dashboard lists the package in "Deprecations / Replacements". See [`../dependency-dashboard-deprecations.md`](../dependency-dashboard-deprecations.md).

The Change cell has no link. The npm manager adds a link to renovatebot.com/diffs, and the nuget manager does not.
